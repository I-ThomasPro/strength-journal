# strength-journal
A simple web app for tracking and measuring training data with an emphasis on strength training.

## Backend

The API is a [FastAPI](https://fastapi.tiangolo.com/) app in `backend/`, using SQLAlchemy 2 and Alembic on PostgreSQL. All routes live under `/api`.

### Prerequisites
- [uv](https://docs.astral.sh/uv/) (installs Python 3.13 for you if needed)
- Docker, for the local Postgres database (or your own Postgres with the URLs in `backend/.env`)

### Quick start
```bash
make db-up      # start Postgres 18 (creates strength_journal and strength_journal_test)
make install    # install dependencies into backend/.venv
make migrate    # apply database migrations
make dev        # run the API on http://localhost:8000
```

Then open:
- http://localhost:8000/api/health to check the API can reach the database
- http://localhost:8000/api/docs for interactive API docs

Settings come from environment variables or `backend/.env`. Copy `backend/.env.example` to get started.

### Tests and linting
```bash
make test       # pytest against strength_journal_test
make lint       # ruff lint + format check
make format     # auto-fix lint issues and format
```

Tests migrate the test database to the latest revision, then run each test inside a transaction that's rolled back afterwards.

### Migrations
```bash
cd backend
uv run alembic revision --autogenerate -m "describe the change"
uv run alembic upgrade head
```

Import new model modules in `backend/app/models/__init__.py`, which registers every model for the app and for Alembic autogenerate. CI fails if the models and migrations disagree (`alembic check`).

### Model conventions
Models live in `backend/app/models/`, one module per table, and build on `app/models/common.py`:
- `UUIDPrimaryKeyMixin`: UUID `id` generated by the app, so records can later be created offline and synced without clashes
- `TimestampMixin`: `created_at` / `updated_at`, both defaulting to now; `updated_at` is bumped on update
- `WeightUnit` (`kg` / `lb`): store it in a `WeightUnitType()` column and add `weight_unit_check("<column>")` to the table's `__table_args__`
- Other fixed sets of values (e.g. `ExerciseType`): define a `StrEnum`, store it in a `TextEnum(MyEnum)` column and add `enum_check("<column>", MyEnum)` to `__table_args__`
- Ordered children (a Routine's workouts, a Workout's exercises, a workout exercise's sets): an integer `position` with `CHECK (position >= 0)` and `UNIQUE (parent_id, position) DEFERRABLE INITIALLY DEFERRED`, so items can be reordered within one transaction. Tests force the check with `check_deferred_constraints()` from `backend/tests/helpers.py`

Model tests use the `db_session` fixture and the factories in `backend/tests/factories.py` (e.g. `create_user(db_session, email=...)`).

### Layout
```
backend/
├── app/
│   ├── main.py          # create_app(): routers, docs under /api
│   ├── config.py        # Settings (pydantic-settings)
│   ├── db.py            # Base, engine, get_db / DbSession dependency
│   ├── models/          # one module per table; common.py holds shared mixins and types
│   └── api/
│       ├── router.py    # /api router
│       └── routes/      # one module per resource
├── alembic/             # migration environment and versions/
└── tests/               # factories.py builds model records for tests
```
